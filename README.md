# AI Traffic Management System

Software prototype for the IT 207 Human Intelligence project. It combines recorded-video perception (YOLO vehicle detection and ByteTrack identity tracking), lane-based traffic analysis, short-term prediction modules, adaptive signal recommendations, a Streamlit dashboard, and a reproducible software-only traffic simulator. It does not interface with physical lights, sensors, or other hardware.

## Current state

The workspace contains the Python application modules and configuration, but no traffic video, labeled detection dataset, YOLO weights, trained prediction models, SUMO installation, or previous experimental outputs were present at audit time. The four-controller comparison included here is generated by the project's seeded software simulator. It is not a real-road or SUMO result. Detection precision/recall/mAP, tracking IDF1/MOTA, and forecast MAE/RMSE have not been measured because their required model, ground truth, and runtime dependencies are unavailable in the supplied workspace.

## Requirements and setup

Use Python 3.11 as specified by `requirements.txt`. Install the pinned project dependencies in a virtual environment:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install --only-binary=:all: -r requirements.txt
```

The requirements file includes PyTorch, Ultralytics, OpenCV, Streamlit, FastAPI, and the prediction and document libraries. GPU use is optional; CPU mode is selected when CUDA is unavailable. The first video-analysis run automatically downloads the official YOLO11n weights to `models/weights/yolo11n.pt` when internet access is available. SUMO and TraCI are optional and must be installed separately; the evaluated experiment results below use the built-in software simulator.

## Run the application

From this directory, launch the dashboard:

```powershell
streamlit run dashboard/app.py
```

Launch the REST API in a second terminal if needed:

```powershell
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

The dashboard includes video analysis, monitoring, prediction, signal optimization, experiments, and methodology pages. Video analysis requires the compatible YOLO weights above. Prediction training also requires the configured ML packages and traffic history. Use the synthetic-data action only for software demonstration; generated samples are not real traffic observations.

### Deploy the dashboard

**Streamlit Community Cloud:** Push this repository to GitHub, create a new app in Streamlit Community Cloud, select `dashboard/app.py` as the main file, and deploy from the `main` branch. `runtime.txt` selects Python 3.11 and `requirements.txt` installs the app dependencies. The app uses a local SQLite database; hosted instances may reset that database when restarted. Do not treat synthetic samples as live traffic data.

**Docker:** From the project root, build and run the included container:

```powershell
docker build -t ai-traffic-management .
docker run --rm -p 8501:8501 ai-traffic-management
```

Then open `http://localhost:8501`. Set the `PORT` environment variable when the container platform assigns a different listening port. The container runs the dashboard; run the FastAPI service separately with the command below if you need the API.

The dashboard can deploy without model weights; recorded-video detection downloads `models/weights/yolo11n.pt` on first use when internet access is available. Model weights, private traffic video, local databases, and virtual environments are intentionally excluded from Git.

## Run the software experiments

```powershell
python -c "from src.simulation.sumo_runner import run_sumo_experiments; run_sumo_experiments('submission/experiment_results')"
```

The configured scenarios compare fixed-time, rule-based, and AI-assisted controllers under identical seeded arrivals and 1,800 simulated seconds. The demand profile is balanced except in `uneven_demand`, where the four approach shares are 55%, 25%, 15%, and 5%. Metrics are estimates from a compact queue simulation; they do not model a calibrated road network, pedestrian phases, turning movements, vehicle startup delay, or coordinated intersections.


## Project map

- `src/detection/`, `src/tracking/`: video vehicle detection and persistent identities.
- `src/analysis/`: lane metrics, queue proxies, traffic states, and synthetic time series.
- `src/prediction/`: Random Forest, XGBoost, and LSTM forecasting implementations.
- `src/optimization/`: fixed, rule-based, and weighted adaptive controllers plus the software simulator.
- `src/simulation/`: SUMO hooks and reproducible software-controller experiments.
- `backend/`, `dashboard/`: FastAPI endpoints and Streamlit interface.
- `submission/`: report, presentation, architecture diagram, viva material, and experiment outputs.

## Experiment summary

See `submission/experiment_results/experiment_results.csv` for the measured results and `submission/experiment_results/experiment_summary.png` for a visual summary. The comparison is a single seeded simulation run per scenario. Results are preliminary and mixed; they do not establish a general improvement for the AI-assisted controller.
